# Tests run hermetically on a SQLite catalog and local files

Production uses a PostgreSQL JDBC Catalog and S3-compatible storage, but the automated test suite uses neither. Fixture Tables are committed to the repo as a local warehouse and loaded through PyIceberg's SQL catalog on SQLite, which has the same `iceberg_tables` layout that change detection queries (ADR-0003). Their files are read from the local filesystem. The UI Backend's tests use a stubbed Prometheus. As a result, the suite needs no services or network: it runs offline in seconds, gives deterministic results, and runs unmodified in GitLab CI. The accepted gap is that S3-specific behaviour, such as object listing in the Orphan Scan, is only exercised by hand against the dev stack (PostgreSQL + MinIO + Prometheus).
